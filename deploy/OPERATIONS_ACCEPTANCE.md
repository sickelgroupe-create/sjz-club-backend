# 上线验收入口：检查不能代替验收

适用本次售后重审、钱包历史分页和支付恢复修复。代码仓库交付的是源码与空库结构，**不是现网数据、支付凭据或已通过真机验收的证明**。目前没有取得本次目标新服务器和真机结果；以下未实测项必须保留“待验证”。

## 1. 新服务器只读检查

先按 [部署入口](README.md) 安装、配置和启动服务。服务实际使用的配置应与检查的文件一致；命令行、systemd drop-in 等覆盖值需要部署人自行核对。用应用服务账号运行：

```sh
python3 deploy/tools/preflight.py \
  --settings-file /etc/sjz-club/settings.env \
  --check-db --check-network --check-local-files
```

依赖 Python 3 标准库、MySQL 客户端及访问目标数据库的权限。不会自动 source/执行配置，不创建订单、不调用微信、不支付、不退款、不修改业务数据。数据库检查在只读事务中执行；Redis仅认证、选择逻辑库和PING；HTTPS仅请求 `/health` 且验证证书、不跟随跳转。单项检查失败不会把凭据、SQL返回明细或原始服务错误写入报告。

- `PASS`：这一技术检查通过，不代表业务验收通过。
- `FAIL`：需修正配置/结构，或人工核对历史异常；退出码1。
- `REVIEW`：未启用/未执行/需人工确认；不应当作已通过。
- `commercial_acceptance` 始终为 `NOT_VERIFIED`；即使技术检查没有失败，也不自动放行商用。

工具检查真实配置是否仍是占位符、正式环境是否误开模拟模式、HTTPS/CORS、精确回调地址、必要表/迁移字段/索引、管理员初始化、虚拟商品现网映射、Redis及目录权限。目录检查是权限元数据检查，不做写文件探针；备份恢复、可用空间、运行进程是否加载同一配置仍需部署人实测。远程Redis只允许可信内网连接，工具不支持Redis TLS/ACL用户名；使用这些扩展配置时需另行检查。

只有 `--settings-file` 时仅检查配置；未传三个检查开关的项目不会被标为通过。输出可保存到仓库外的受限目录给部署负责人核对，不要上传真实配置或账目明细。

## 2. 数据库升级与历史核账

新空库：`001-schema.sql` → `002-seed.sql` → 私密管理员初始化。当前为75表；工具验证实际表名与001一致，不再依赖固定旧表数。

旧库：备份、验证备份可恢复、停服务，按 [数据库说明](../database/README.md) 比对缺失的迁移。售后重审新增 `club_aftersale_admin_request` 历史表，不能只替换jar。钱包分页新增 `(user_id,id)` 索引；不删除或重写历史流水。

历史核账先运行 `database/commercial-preflight-readonly.sql`（建议低峰、只读账号或一致性备份），再核对微信商户/虚拟支付/Apple提供的交易与退款记录：

| 核对对象 | 不能跳过的规则 |
| --- | --- |
| 订单、渠道收款 | 交易号、商户订单号、用户归属、环境、币种和实付金额全部一致；“支付窗口能打开”不等于收款成功。 |
| 退款 | 本地退款意图、渠道退款号、状态和金额逐笔一致；异常/关闭或缺少本地意图的单据需人工处理，禁止直接改成成功。 |
| 钱包、冻结、流水 | 核对当前余额与末条快照，再核对全量账变、冻结和结算；末条一致不保证整个历史链条正确。 |
| 服务方追偿 | 部分回收不能标结清；人工核销须有原因和真实依据，不能当成实际回款。 |
| 迁移完整性 | 一致性备份、图片/语音文件、原身份加密密钥、证书均需安全交接；代码仓库不包含这些。 |

本次不自动修正历史资金、不请求真实退款。若有异常，应在备份上复现、整理差异单并由负责人确认处理方案。没有渠道对账资料，不得将历史账目写成“已核清”。

## 3. 真机验收表（当前待人工实测）

分别使用Android和iPhone，记录机型、系统/微信版本、构建版本、结果及脱敏截图。仅允许隔离测试账号/订单；禁止为了填表把未验证改为通过。

| 场景 | 操作与通过条件 |
| --- | --- |
| 登录/绑定 | 手机密码登录后浏览、资料可用；支付/提现仍按规则要求绑定；原生微信和手机号授权成功、拒绝、取消分别能恢复。 |
| 售后重审 | 测试售后驳回后，由有权限管理员填写原因重审；原日志仍可见，状态回到平台审核；重复点击不重复改状态，无权员工不能操作。 |
| 排行榜 | 0人有空态；1、2、3人有前三名且不出现“暂无排行数据”；4人以上正常显示后续列表。 |
| 钱包历史 | 准备超过100条模拟流水，持续翻页全部可达；断网重试不丢不重，退出切号不显示原账号数据；新增流水后刷新可见。 |
| 录音/上传 | 首次允许/拒绝麦克风、相册、摄像头；取消/断网/退出再进可恢复；语音试听及头像上传后保存。 |
| 海报/扫码 | 生成、保存、历史海报再开、小程序扫码和返回栈正确；拒绝相册权限可再次操作。 |
| 支付展示 | 分别确认Android虚拟支付/iOS Apple入口、金额、取消返回与订单状态；仅“打开窗口”不得填写真实支付通过。 |
| 账号与网络恢复 | 会话过期、刷新失败、切账号、连续点击、断网重连、前后台切换不丢草稿、不串页、不重复提现/退款。 |

按用户当前限制，不进行实际支付和退款。真实收退款链路因此保持未验证；既有用户自测可作为线索，但不能冒充本轮验收证据。
